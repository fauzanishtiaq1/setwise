# Setwise research record

## Product decision

Setwise is a local, dependency-free calibration utility for selecting the smallest
prediction-set parameter whose **expected monotone loss** is controlled. A user supplies
per-example losses evaluated on an ordered grid of parameters (for example, false
negative proportion for multilabel prediction sets); Setwise returns the selected
parameter, empirical risk, finite-sample correction, and audit metadata. This is useful
when a model already exists and the expensive/repeated part is converting a calibration
file into a defensible operating point. It does not train models, fetch data, or claim
conditional or individual coverage.

## Primary paper and implemented mapping

The governing primary source is Angelopoulos, Bates, Fisch, Lei and Schuster,
“Conformal Risk Control,” published as an ICLR 2024 conference paper:
https://openreview.net/forum?id=33XGfHLtZg (PDF:
https://openreview.net/pdf?id=33XGfHLtZg). The authors define losses
`L_i(lambda)=ell(X_i,Y_i,lambda)` that are monotone in a scalar parameter and select a
parameter from calibration examples to control expected test risk; examples include
multilabel false-negative proportion, segmentation false-negative rate, hierarchical
classification graph distance, and QA token F1. The authors' accompanying repository
is public and MIT licensed: https://github.com/aangelopoulos/conformal-risk.

Setwise implements the paper's **one-dimensional, split calibration use case** only:
bounded losses in [0, 1], a finite ordered parameter grid, and a declared monotone
direction. For each parameter it applies the paper's expectation-control inequality
`(n/(n+1))*Rhat(lambda) + B/(n+1) <= alpha`, with `B=1` for [0,1]-bounded losses.
Equivalently, the additive correction to the empirical mean is
`(1-Rhat(lambda))/(n+1)`. There is no confidence-delta parameter in this expectation
guarantee. For nonincreasing risk, Setwise selects the smallest admissible parameter;
for nondecreasing risk it selects the largest admissible parameter. The implementation
must cite the paper next to the equation and include a reference test against
hand-computed toy losses.

Explicitly omitted: distribution-shift extensions, quantile/multiple/adversarial risk
control, U-statistics, adaptive/conditional risk control, non-monotone losses,
multi-dimensional parameters, model fitting, neural-network inference, and any claim
of subgroup or per-example guarantees. These omissions keep the core auditable and
stdlib-first rather than pretending to reproduce the paper's full research code.

## Competing tools and honest differentiation

MAPIE is the closest mature alternative. Its documentation exposes split conformal
regression/classification and risk controllers and requires NumPy/scikit-learn:
https://mapie.readthedocs.io/en/stable/content/conformal-prediction/ and
https://github.com/scikit-learn-contrib/MAPIE. MAPIE is preferable for fitted
scikit-learn estimators, prediction intervals, and many production methods. The
official CRC repository provides research examples but is PyTorch/data-pipeline
oriented: https://github.com/aangelopoulos/conformal-risk.

Setwise's defensible niche is smaller: a zero-dependency, file-in/file-out calibration
step that accepts losses generated by *any* model or language and emits deterministic
JSON suitable for CI, batch jobs, and review. This is an integration/portability
difference, not a novelty claim and not a claim that Setwise is faster. No measured
time saving exists until the validation leaf runs the prescribed benchmark.

## Rights and provenance

The paper is a scholarly source; Setwise will independently implement the described
mathematics and will not copy source code, paper text, model weights, or datasets.
The cited official reference implementation is MIT licensed, but that does not grant
patent clearance or make its assets part of Setwise. Original Setwise code is planned
to be MIT licensed. Test fixtures are synthetic and authored in-repo. Users remain
responsible for rights to their calibration data and for checking any jurisdictional
patent/licensing issues; this note is not a legal opinion.

## Reproducible usefulness evaluation

The validation leaf must run a seeded synthetic multilabel fixture and report the
following raw values in JSON: n, grid size, alpha, selected parameter,
calibration empirical risk, correction, and held-out risk on a separately generated
exchangeable test sample. The baseline is a short Python standard-library script that
scans the same grid but selects by empirical risk alone (no CRC correction). Compare
both methods on at least 30 fixed seeds; report coverage/risk-control pass rate and
selection conservatism. Do not claim a guarantee from this finite experiment and do
not claim human time savings. Also benchmark wall-clock time for Setwise CLI versus the
baseline on the same files, reporting machine and input sizes; a null or slower result
must be retained.

## Critic pass / limitations

The guarantee relies on exchangeability (or the assumptions stated by the paper),
bounded losses, correctly ordered monotone parameters, and an independent calibration
sample. A malformed or non-monotone loss table can produce a plausible but invalid
answer, so validation must always reject NaN, out-of-range losses, duplicate
parameters, and monotonicity violations. Small n or a finite grid can make every grid
point inadmissible; this is a valid `no_solution` result, not a bug or a guarantee that
an operating point exists. Marginal expected
risk control is not conditional coverage, fairness, temporal-robustness, or a safety
certificate. All such limitations must appear in CLI output and README.
